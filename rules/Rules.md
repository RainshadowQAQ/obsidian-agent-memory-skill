# AI 使用规则

适用范围：本知识库的读取、整理和更新。共同规则需要各 Agent 实际加载才生效；规则文件的存在不代表工具已完成配置。

设计背景见 [[Harness|Harness]]。

## 忠实记录，不替用户补全

- 区分用户明确表达、AI 建议、已确认决定、待验证判断。用户沉默不视作接受建议。
- 不新增用户未表达的目标、期限、动机或承诺；保留否定、条件、犹豫程度和适用范围。
- 模糊、矛盾和尚未决定的想法都是有效内容。不强行统一，不替用户选择，也不要求用户先想清楚。
- 整理阶段不预设未来执行任务的澄清条件。实际任务的提问留给当时的 Agent 对话处理。
- 简短认可必须联系被认可的具体内容，不扩大认可范围。

## AI 自行整理和核验

1. 读取已有主题与当前可访问的来源，仅提取有价值的变化。
2. 生成更新后逐项对照原始材料，检查是否遗漏条件、改变确定程度，或把建议变成决定。
3. 原话必须逐字核对并保留必要语境；无法访问的原文不补造，明确来源限制。
4. 核验发现问题由 AI 修正。依据不足时降低概括程度、保留原话或保留不确定状态。
5. 保存后重新读取，检查内容、实际链接及改动范围。失败如实报告，不声称已经保存。例行保存可只回读改动段落，并用 `python3 tools/kb.py check` 检查链接。

日常核验不交还用户逐条审批。不要仅靠“另一次摘要”核验前一次摘要。

## 保存与组织

- 文件名与 tags 使用英文；正文可使用中文。
- 默认一主题一篇笔记：目的与约束、当前状态、重要决定及原因、未决想法、必要依据；没有内容的栏目可省略。
- 分层组织：**领域 → 首页 → 子笔记**。新笔记须写 `area`、`kind`，并从所属首页链接；知识库根目录 `README.md` 只列领域与首页；子笔记索引与证据入口放在首页。
- 新内容并入对应段落，条目可标日期；不在笔记底部追加按日期命名的整节。底部只留简短“更新记录”。内容拆分或移动时原文不改，并在更新记录说明去向。
- 代码与修改历史留在项目及 Git；笔记记录文件位置和已验证的提交编号，不重复保存完整源码、依赖、构建产物或冗长日志。
- 仅更新相关内容；无变化不写入。同一材料再次整理不产生重复条目。
- 不擅自批量拆分笔记、扩展分类、制定计划或生成新技能；需要明确授权才开展这些工作。

## 关系图谱与引用

- 图谱节点是笔记，连线来自实际内部链接。标签用于筛选和分组，不代替语义关系。
- 在正文“相关笔记”或具体论述处，链接确实相关且已存在的笔记，说明关系。无需在两边重复同一链接，Obsidian 会显示反向链接。
- 内部链接统一从知识库根目录起算（或使用唯一文件名），不使用本机绝对路径。
- 不为增加连线创造没有依据的关系，不把空白测试页当成已通过的验证。

## 多工具读写边界

- 不同 Agent 的目录权限、规则加载与触发方式需分别验证。共享目录不等于已自动接入。
- 写入前重新读取目标，避免覆盖其他更新。未实现显式锁或串行写入入口前，不声称支持并发写入。
- 不得把本地文件历史视为独立备份，不自动删除用户原有内容。
