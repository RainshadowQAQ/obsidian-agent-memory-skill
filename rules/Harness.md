# 跨 Agent 本地知识库 Harness 设计

本文件记录个人多 Agent 协作知识库的定位、边界与工程取舍。具体读写与核验规则见 [[Rules|Rules]]。

## 目标与约束

- 用本地 Markdown 目录（Obsidian Vault）保存跨会话沉淀的背景、决定与依据，让不同 AI Agent（例如 Codex、Claude Code、Kimi / Kimi Code、DeepSeek Harness）能够续接工作，减少重复输入。
- 优先纯本地文本文件与简单目录结构，不依赖额外存储设备或自建网络服务器。
- 整理与核验由 AI 执行，避免把“逐条核对摘要是否失真”的负担交还给用户。
- 代码与修改历史留在各自项目的 Git 仓库中；知识库只记录项目位置、关键决定与已验证的提交编号，不复制完整源码、依赖或冗长日志。

## 保存方式的选择

采用**“主题笔记 + 必要原话片段”**，默认一主题一篇，保留目的与约束、当前状态、重要决定及原因、未决想法和必要依据。

与“全文加摘要”或“只存摘要”相比，这种方式能控制上下文读取体积，同时保留关键依据用于回溯；代价是不能完整重建所有历史对话细节。

## 关系图谱与脚本边界

- **图谱连接**：Obsidian 关系图谱连接笔记节点，不自动解析代码依赖。软件项目通过项目主题笔记链接相关知识与决定，在笔记内标明实际源码路径。
- **确定性辅助**：通过 `tools/kb.py` 提供按标题/行号/来源编号读取的片段检索与链接校验，避免 Agent 每次全量读取长文件，也减少纯靠 Prompt 记住目录规范导致的链接漂移。
- **并发与历史边界**：多工具共享同一本地目录不等于天然支持并发写入。写入前需重新读取目标文件；可靠的并发保护需要显式锁或串行写入入口。
